# v0.8.0 — Reviewed evidence and workflow continuity

Released on 2026-10-10.

## Highlights

- Connect reviewed evidence and research questions to exact Thesis revisions,
  recoverable Decisions, versioned Plans and explicit Retro follow-ups.
- Make review work easier to resume: preserve tab-local drafts, compare readable
  finding changes, inspect related historical reviews in place, and prioritize
  overdue/conflicted follow-ups without changing their dispositions.
- Strengthen market-data identity, cutoff, session and short-history handling,
  keeping missing facts and provider limitations explicit.
- Preserve the owner-review boundary. No autonomous research confirmation,
  broker refresh or general unattended order authority is added.

## Upgrade and compatibility

- Migration head is `0073_research_evidence_links` (previous release: `0072`).
  Back up the installed database before explicitly running `trading-partner-init`.
  Startup and ordinary reads do not migrate. Restore a verified backup for rollback.
- Reconnect MCP clients and rediscover exact operation schemas after upgrading.
  Optional Retro follow-up fields preserve legacy requests and review records.
- Scorecard S1-v3 separates assessed Evidence and reviewed Impact cohorts while
  preserving historical S0/S1-v1/v2 records. No aggregate quality score is added.
- Local review drafts are tab-scoped, bounded and expire after 24 hours. Reload of
  an unresolved review only reads the original receipt; replay remains explicit.

## Acceptance limits

Automated synthetic checks cover facts, scopes, versions, authorization, recovery,
packaging and UI interactions. Independent semantic holdout review and measured
human task-time improvement remain pending. This release does not claim improved
investment returns or completed W19 human acceptance. W20 remains conditional on
measured Research latency. Publishing this release does not upgrade a running host.

## Dependency security updates

- Update the locked Python dependencies PyJWT, pypdf, soupsieve, urllib3 and
  Werkzeug to audited fixed versions; require pypdf 6.20.0 or later for PDF extras.
- Update Next.js to 16.3.8 and override brace-expansion 5.0.12, sharp 0.35.5 and
  source-map-js 1.2.2 to address dependency audit findings.

## Final review usability improvements

- Compare only changed finding fields using readable labels instead of raw JSON.
- Open the exact related historical Run in place, retaining the current draft and
  position; unavailable history remains explicit and does not trigger a write.
- Sort actionable overdue work before conflicts, evidence gaps and future/completed
  items. Sorting is presentation-only and never resolves, hides or confirms work.

## Market-data correctness and technical history

- Pin one effective `as_of` through unified market-to-US delegation, avoiding
  different observation cutoffs inside a single quote, bar or context request.
- Preserve MID provenance when deriving a spot quote from bid/ask, keeping the
  spot/future price-basis mismatch gate effective.

- Verify Yahoo, Moomoo overnight and Alpha Vantage response identity before assigning
  the requested Instrument. Reject ambiguous or mismatched responses.
- Use exchange-session close times for US daily facts, including early closes.
  Alpha Vantage date-only closing quotes retain REGULAR provenance. Non-session
  daily rows are explicitly warned; unavailable calendars fail closed.
- Build Yahoo weekly/monthly bars from cutoff-visible daily facts, preserving
  adjustments and disclosing partial calendar periods.
- Keep available weekly technical facts for short histories; mark unavailable
  metrics and incomplete history explicitly. SMC skips percentage FVG calculations
  with nonpositive opening prices and discloses the limitation.
- Keep synthetic Decision Replay revisions and assumptions independent of current
  Thesis state, and exclude impacts confirmed after the reviewed cutoff.
- Isolate the MCP stdio integration test from owner runtime files. Source releases
  exclude local runtime state, dependencies and Console build outputs; CI inspects
  both source and wheel archive member boundaries.

## Market reliability and review scope

- Gate Yahoo metal daily facts by their supported ending-trade-date completion
  policy. GC=F and specific contracts use a disclosed conservative 17:00 New York
  bound; other seeded continuous proxies retain prior native date labels with
  completion explicitly unknown. Preserve actual timestamped quote recovery and
  disclose derived daily quote times. Version futures cache keys to bypass old
  16:00 entries. Reject repeated local daily dates even when native timestamps
  differ, before period volume aggregation. No exact holiday-close or executable-
  price claim is introduced.
- Synchronize generated Console request types with the existing optional Question
  context token; backend schemas are unchanged and the contract check passes.

- Disclose unavailable overnight coverage for non-overnight fallback quotes,
  including cached results. Classify open Provider circuits as retryable
  unavailability while preserving skip and fallback behavior.
- Clip Dukascopy historical bars at their native interval completion time,
  including legacy fallback, preserving raw opening timestamps and OHLC. Reject
  wrong/ambiguous legacy quote identities and validate historical buckets before
  caching, allowing recovery on the next explicit read after malformed data.
- Disclose partial weekly boundaries and available-prefix SMC confirmation in
  snapshots, Console charts and standalone PNGs; keep calculations unchanged.
  Preserve these caveats and source coverage notes through the explicit Chart-to-
  Research review and draft handoff, with bounded optional session metadata.
  Date-only futures label derived SMC timestamps explicitly, disable historical
  chart cutoffs and reject cutoff-based Research handoffs without changing the
  underlying candles or calculations.
- Release disconnected SSE delivery queues while durable turns finish.
- Exclude confirmations arriving after the sampled Research Links cutoff with
  explicit partial coverage. Bind Cycle Preview and Apply to the reviewed
  payload, scope and key; preserve drafts through stale responses and failures.
  Verify Cycle Preview and saved receipt identity, members, reviewed note and
  authorization note before clearing a draft or uncertainty; unknown
  responses retain the original key and require explicit follow-up. If the draft
  changes while Apply is unresolved, retain both the original request and new
  draft; block another Preview until exact receipt recovery or explicit same-scope
  retry resolves it. This recovery state lasts while the editor remains mounted.
- Prefer the correct BUY/SELL quote side for broker preview references, disclose
  context-only fallbacks, and keep freshness separate from those warnings.
  Existing account restrictions and order submission behavior are unchanged.

## Review draft continuity and interaction checks

- Preserve Retro drafts and original pending requests across same-tab navigation
  and reload with bounded session storage; storage failure is explicit.
- Keep drafts through review version conflicts and show saved-versus-draft
  differences. Explicit rebasing updates the local basis without submitting.
- Verify populated narrow-screen forms and keyboard actions, partial Question
  proposal followed by return, and reload recovery with no automatic POST.

## Retro save-response recovery

- Recover a committed review from its exact Run/request-key receipt after response
  loss, without resubmitting. An unresolved response retains the submitted payload
  across same-tab reload; only explicit retry can replay that same idempotent request.
- Added receipt scope/read-only checks and browser regressions for committed response
  loss and an uncommitted request. Broker UNKNOWN outcomes retain their separate
  no-retry boundary.

## Follow-up experience and acceptance boundaries

- Prioritized due/changed/missing-evidence next steps inside existing Retro reviews,
  with detailed counts collapsed and direct navigation to the linked Question.
- Added bounded selected-follow-up denominators and exact-version traceable-review
  checks. Closed status, later profit and absent later findings do not prove closure.
- Added a checksum-pinned synthetic semantic review corpus and separate unreviewed
  dimensions to the existing evaluator; automated gates do not certify semantics
  or user time savings. No usage telemetry or runtime authorization was expanded.

## Review calibration and follow-through

## Review workflow continuity

- Connected synthetic Today, Research, Quick Review, Changes, Evidence and Replay
  fixtures through exact identities, with real preview-route checks for unknown
  scopes, empty/error states and disabled writes.
- Added an independent human Decision entry from FULL notes, including failed or
  absent interpretation. It preserves exact scope, empty user rationale and separate
  Observation disposition. Decision source checks enforce FULL coverage and aware
  visibility at the decision time.
- Saved Quick Review material references atomically with each Decision through a
  linked Journal NOTE. Completion/recovery returns the original prepared context,
  coverage and pending-note count; an unknown count remains unavailable. Reload
  checks unresolved submissions without preparing or posting a new attempt.
- Extended explicit Review Queue refresh to two bounded, paginated source scans,
  safe completeness checks and a durable audit receipt. Partial scans cannot close
  unseen items; receipt failure does not repeat reconciliation. GETs stay passive.
- Stopped Operational Jobs on heartbeat failure and hardened cancellation/finish
  recovery. Unknown terminal writes are read back once, never retried; a recovered
  interrupted receipt cannot reuse a success value.
- Preserved Journal note selections across context refreshes and added focused
  tests for manual review, source separation, material rollback, multi-account
  references, restart, lost responses and queue coverage.
- Fixed concurrent diagnostic SQLite WAL initialization within the existing
  bounded wait and closed failed setup connections without replaying invocations.

## Other changes

- Extracted shared synthetic evaluation ports and fingerprints so live research
  acceptance no longer imports the Console API or its optional web dependencies.
- Corrected current Agent channel, proposal-authority and native-search guidance.
  Console defaults, budgets and user model preferences remain unchanged.
- Prevented a narrow field-certainty explanation from being mistaken for an
  execution confirmation; financial confirmation claims remain rejected and
  accepted explanations remain unverified inference.
- New Research messages carry host-generated structured evidence presentation,
  avoiding prose reparsing for field display while retaining exact original text,
  bounded receipt compaction and historical-message fallback. Missing/null versus
  zero definitions no longer require a Chinese-only wording workaround; actual
  financial amounts retain exact field binding.
- Observation refresh prepares each review context once and reuses it for the
  conditional draft call; successful-draft reuse, request limits and review gates
  remain unchanged.
- Consolidated equivalent Console value conversion and Agent date formatting,
  preserving each surface’s missing-value, whitespace, array and numeric behavior.
- Separated Journal behavior metric presentation from page state and replaced
  redundant source-text assertions with browser checks for inconsistent rates and
  supplied counts. Telemetry now reads the authoritative application version.
- Shared application-layer ReviewItem projection and successful-page observation
  between global and scoped refresh. A composed application service now owns bounded
  source collection and explicit materialization, preserving failed-source and
  paginated-source closure boundaries, existing links and read-only Journal behavior.
- Isolated bounded Research evidence finalization from event and persistence
  orchestration while retaining one shared terminal message/turn path.

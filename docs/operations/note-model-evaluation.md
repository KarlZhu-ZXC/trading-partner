# 笔记解析模型评测

目标是忠实保留作者、日期、意图、数量、价位及执行状态，同时测量任务能否完成。
开发继续使用 Codex；此工具比较 Go、Zen 与官方 OpenCode CLI 的笔记解析，
不更新笔记、研究判断、持仓或订单。
日常模型与默认 `max` 推理不随评测改变。降低档位时，请求及结果记录必须使用同一档位。

**模型比较只使用真实案例；实时调用须有当前用户的明确指示。**
用户纠正并由已保存交易记录证实：一个真实 TP 样例此前被错误标为未成交计划。
受影响运行目录已追加 `baseline-correction.json`，其旧内容总分和模型排名暂停采信；
原始输出及连接失败记录保留。修订语料 `real-notes-v2.json` 仅保存在所有者私有目录。
下文历史分数不代表修正后的准确率。合成夹具不再用于本次模型选型。

用户随后明确授权继续评测。修订语料 `real-notes-v3.json` 保持八篇正文原样，
通过独立 `interpretation_context` 传递用户澄清与相关持久化交易上下文；runner
将该字段实际加入模型输入，不发送人工评分 rubric。只选取不晚于笔记观测时间的
交易，保留来源、事件日期及历史覆盖缺口，不用后来的持仓快照重写当时观点。
TP 提示已改为根据上下文区分计划、挂单和已成交，不再一律视为未来意图。
这次输入与提示均变化，必须作为新实验，不能与旧分数直接作同条件比较。

此次人工评测分别记录完成状态、核心忠实度、辅助字段问题。错认本人重要意图、
成交状态、作者、数字、条件或时间，以及遗漏重要计划或凭空添加交易指令，属于
核心错误。没有执行后果的周期分类或枚举措辞、非关键摘要详略只作辅助记录，
不单独否决整篇。程序作者分段兼容性属于流水线校验；它不是语义作者归属的标准答案。

提示词后续修订明确区分意图提取与策略完整性：明确买卖不因缺少止损等信息而降为
无意图；缺项独立记录。段内引用使用原 block 标签，摘要和价位保留实际被引用作者；
按作者合并不同日期，减少重复免责声明并保留重要历史动作。修复调用收到具体的
工具调用、作者匹配、JSON 或 schema 错误提示。该修订没有放宽校验器或改变输出 schema，
模型效果必须另用同输入真实案例验证，不由本地单元测试推断。

该修订用三篇已授权真实案例、Luna medium 与 Grok 4.6 medium 验证，两次运行的

第二版六项均首次返回、核心通过 6/6，两个模型都保留了段内被引用作者。
周期推断、枚举措辞及缺项表述不一致仍记为辅助问题，不宣称全文零错误。
这只是三篇定向回归，不替代八篇全量模型排名，也不能证明网络或上游服务问题已解决。

## 用例与隐私

- `tests/fixtures/note-interpretation-cases.v1.json` 是版本化的纯合成用例，含人工核对标准和
  少量确定性的行动枚举断言。覆盖 TP、采纳区间、提问与决定、撤回、条件动作、引用注入、
  数字更正、混排价位、价位角色、方向与操作、挂单状态、明确不跟随、记录与事件日期、
  不同仓位目标、否定句风险偏好、预测期限与持仓周期。
- 真实笔记语料、评测结果和人工审阅必须放在仓库外的所有者私有目录；目录权限为 700，
  文件权限为 600。真实内容不得复制到 Git、测试夹具、诊断日志或发布包。
- 私有语料需要当前任务的明确用户授权，并在命令中传入 `--authorize-private`。
  已保存语料或过往授权不构成未来自动调用许可。这个开关只传达授权，不替用户授权。
- 私有用例可以保留用户明确纠正的语义和预期，例如 TP 的卖出意图；不能把模型输出
  或多数模型的一致意见直接当作正确答案。来源正文保持原文，澄清记录单独保存。
- 不需要维护另一套应用数据库或日常状态。用例以 JSON 文件版本化，测试按需运行。

## 执行

默认只验证语料并展示任务数，不调用模型：

```sh
uv run python scripts/evaluate_note_models.py --variant deepseek-flash:high
```

运行合成测试并把结果保存在仓库外：

```sh
uv run python scripts/evaluate_note_models.py \
  --variant deepseek-flash:high --variant deepseek-flash:max \
  --variant gpt-6-luna:high --variant gpt-6-luna:max \
  --run-dir "$HOME/.local/share/trading-partner/note-evaluations/runs/synthetic-v1" --live
```

授权的真实语料可另加 `--corpus /absolute/private/corpus.json --authorize-private`。
官方免费 CLI 使用 `--provider opencode_cli` 和
`--variant deepseek-v4.1-flash-free:provider_default`；可用
`--cli-executable /absolute/path/to/opencode` 指定程序。CLI 复用正式隔离适配器，
只允许其免费模型白名单，不把服务默认档伪称为 `max`；不支持 `--direct`。
该模式的 `catalog.json` 仅证明本地白名单，实时可用性、免费政策与上游版本须另行核实。
`--cases id_a,id_b` 选择用例；`--repeats 2` 重复；`--concurrency 4` 限制并发；
`--timeout 300` 是每次模型调用上限。原服务允许一次格式修复，因此单轮解析可能超过这个时间。
`--max-retries 3`（默认）表示首次失败后最多再执行三轮解析，共四轮；0 关闭自动重试。
仅超时、服务不可用、限流且未标记不可重试的失败可重试，间隔为 1、2、4 秒；
鉴权、请求拒绝、无效结构及内容错误不触发该重试。每轮保存独立结果与安全诊断，
底层协议已有的有界重试和格式修复仍单独存在，所以四轮不是四次 HTTP 请求的保证。

`--direct` 仅用于独立连接对照：不使用配置代理或环境代理，清单记录连接条件；
不会更改日常网络配置。连接路径不同必须使用新运行目录。

使用相同命令和结果目录会跳过已记录任务；`--retry-failed` 显式补跑失败项，保留原失败
记录，不覆盖成功结果，也不绕过可重试分类或重置累计四轮上限。语料、代码、档位、
重试预算、超时或并发不同，必须用新结果目录，不能混合
成一轮。模型和档位先对照实时目录验证；工具记录的是适配器公布的支持情况与实际发送
的档位，不能证明上游内部用了多少思考。Contributor 模型默认排除；只有用户另行明确
允许所选私人语料用于训练或改进，才可在该次评测使用
`--authorize-contributor-training`，不改变正式运行时的训练授权配置。

### 所选 Go / Zen 模型的原生接口

`--documented-protocols` 使用独立评测适配器，按所选模型的官方接口发送请求：
Chat Completions、Responses、Messages 或 Google 原生函数调用。该适配器不接入正式
fallback，不更改应用校验器。协议与档位保存在 `catalog.json` 的 `frozen_profiles`，
实际请求正文另存 `wire_request_snapshots`；不保存请求头和凭据。
支持指定强度的模型记录实际请求档位，其余记录 `provider_default`，不能宣称内部推理相同。

该模式要求串行且无外层重试；本轮固定每篇一次、每次调用上限 300 秒和最多一次结构
修复。Go Chat/Responses 不发送本地输出上限；Messages 及 Google、Zen 免费入口使用
32,000 输出预算。遇到鉴权或请求拒绝，暂停该模型剩余任务并保存 `stopped-*.json`，
续跑也不会自动重试被暂停模型。限流仍停止全批派发。

不允许额外余额扣费的 Go 评测，先由用户确认 Console 的 Extra usage / Use balance
已关闭，再传 `--confirm-go-extra-usage-disabled`；目录及配置接口不能证明此账户开关。
地区受限模型须先核对实际使用地和账户地区，不通过切换代理绕过限制。
Zen 所选免费入口单独保存运行目录，不能把同名 Go 和 Zen 输出混为一组。

## 结果与验收

每项完成即写入一个所有者私有结果文件，可中断后续跑；同一目录禁止并发写入。
`manifest.json` 保存语料与代码指纹和比较条件；`catalog.json` 保存目录检查；结果保存
模型、档位、修复调用次数、耗时、上游返回模型名和可用的 token 用量。终端只显示匿名
任务标识与状态，不打印正文、模型输出或供应商原始异常。
新运行另存完整 `corpus.json`、相关提取源码快照，以及每次服务调用的
`request_snapshots` / `response_snapshots`，用于离线核对请求和模型输出。
这些含私人正文的资料只进入所有者私有结果目录，不进入诊断日志；CLI 的实际文本封装
由保存的适配器源码复现，底层没有公开的模型构建版本或 token 用量不得推测补齐。
`failure_diagnostics` 只保留可用的 HTTP 状态、封闭的连接错误类型、是否可重试及
有界的底层尝试次数；不保存异常消息、响应正文、URL、请求头或凭据。旧记录没有这些
字段时不能倒推出具体网络根因。补充诊断改变代码指纹，后续实时验证使用新目录，
不覆盖历史失败或将新结果补写成旧请求的结果。

结果中的 `repair_errors` 另存首次输出被拒绝的封闭错误码及调用序号；格式修复后
成功也保留该错误。`errors.json` 汇集失败轮次、供应商调用失败、修复前拒绝和人工
内容错误及辅助缺陷。不同层事件可能描述同一次失败，不能把事件数相加当作失败任务数。
底层 HTTP 重试只记录适配器提供的尝试次数，不假装取得逐次原始响应。

默认遇到首个限流错误就停止派发新任务及额外重试，已开始的调用完成后保存汇总和
`pause.json`；避免共享限额耗尽时连续消耗整批预算。尚未派发的任务保持未执行状态，
已返回失败仍算失能；恢复时使用同目录的剩余预算。只有显式
`--continue-on-rate-limit` 才继续限流后的派发。更改并发或采用完整新一轮复测时使用
独立目录，记录这是新实验，并保留旧轮结果。

`reviews.json` 的 `results` 按 `job_id` 填写人工判定，例如：

```json
{"job-id": {"verdict": "FAIL", "findings": ["遗漏本人明确的参与意图"], "source_blocks": [0]}}
```

`PASS` 必须核对原文含义、遗漏、额外断言、作者及日期；只有行动枚举检查通过不等于
语义通过。改完人工判定后重跑相同命令会跳过已有调用并重算汇总。

**超时、供应商失败、无效输出都算失能，不能从分母剔除。** 汇总分别显示：

- 计划任务数、返回成功、失能、尚未执行；尚未执行不伪装成模型失败。
- 失败调用与失败原因、补试后恢复的任务；补试成功不抹掉首次失能。
- 成功输出中的明确约束失败、语义失败和待人工审阅。
- 端到端通过数／全部计划任务数。人工审阅未完成时，只是暂定下界，不是最终准确率。

提高或降低推理档应同时看端到端通过、意图遗漏、错误条件及耗时。不因输出更长、
更加保守或单次成功就升级模型；也不能将更快但遗漏计划的输出当成改进。

## 增加模型与用例

新增模型通过 `--variant MODEL:EFFORT` 加入；模型协议是否兼容仍以实时调用验证。
新增用例包含 `id`、`body`、`rubric`，可选 `title`、`observed_at`、`expected_actions` 和
`previous_payload_json`。`expected_actions` 映射情景名到允许的行动列表；只对明确无歧义
的约束使用，避免把宽泛词语匹配伪装成准确性评分。每个新缺陷先写清正确含义和证据，
再用完全虚构的标的、价位和场景编写可提交的回归例，不改写历史用例来迎合某款模型。

当时同批其他协议模型仍成功。随后用无私人内容的请求，通过配置代理与直连分别检查
high/max，四项均 HTTP 200；再通过配置代理完成完整解析协议的两项合成样例，high
约 20 秒、max 约 147 秒返回且结构合格。此结果未复现固定的档位或协议不兼容，
但不证明历史故障已根治，也不算补试替换原失能。历史记录缺少 HTTP 状态或连接异常
子类型，只能定位到请求/传输失败，无法确定当时是代理连接还是上游 5xx；新的安全
诊断字段用于下次区分，不能据推测回填旧记录。

累计语料为 16 个可提交的纯合成用例和仓库外的 8 篇私有真实样例；本轮实时矩阵只选
其中 3 篇真实难例，不能声称 16 个合成用例均已通过各模型。新发现的一般错误模式已
补为合成回归用例，来源正文和逐项审阅只保存在所有者私有目录中。未切换日常模型。


### 加入三次重试后的同输入复测

在相同三篇真实样例上复测 Luna high/max。每轮首次请求的指纹与原比较一致，包括
恢复任务的第二轮；只增加瞬态失败重试预算，不因内容错误重复抽取。

| 档位 | 首轮结构合格返回 | 失败轮次 | 重试恢复任务 | 最终结构合格返回 | 原文核对通过 |
| --- | --- | --- | --- | --- | --- |
| high | 3/3 | 0 | 0 | 3/3 | 0/3 |

max 的一项长笔记首轮 300 秒超时，第一次重试约 256 秒返回；含 1 秒退避共约
557 秒。原超时作为独立失败轮保留，总共六项任务、七轮解析；底层格式修复单独计数。
high 的三个结果分别出现压力位误写现价、遗漏历史采纳关系、改变固定作者归属的问题。
max 同样遗漏历史采纳关系；其 TP 意图已完整进入情景条件，但行动枚举仍保守地标为
REVIEW，作为改进项记录，不等同于此前完全漏掉卖出安排。

本轮实测证明一次超时可以由重试恢复，不能证明所有瞬态故障都会恢复。未使用内容

稳定性的保证；日常模型、推理档与运行服务均未因此切换或部署。

### GLM 与 Grok 扩展比较

同三篇困难样例、300 秒调用上限、最多三次额外重试、并发 3。
下表保留原始返回计数，同时将事后发现的无效作者归属计入有效失能。
旧结果文件保持原样，私有目录另存人工审阅与归属校验审计。

| 模型／档位 | 原始返回 | 有效失能（含归属无效） | 端到端通过 |
| --- | --- | --- | --- |
| GLM 5.3 high | 3/3 | 1/3 | 0/3 |
| GLM 5.3 Flash high（修复参数前） | 0/3 | 3/3 | 0/3 |
| Grok 4.6 medium | 3/3 | 1/3 | 2/3 |
| Grok 4.7 medium | 1/3 | 2/3 | 0/3 |

GLM 5.3 与 Grok 4.6 均有两项连接失败后恢复，不能把最终返回率称为首轮可靠性。
Grok 4.6 两项通过、另一项改变已确定作者归属；GLM 5.3 另有额外关联收益目标、
推断持有周期的问题。Grok 4.7 唯一返回也推断了外部作者的持有周期。
预测期限不自动等于持有周期，未明确时应保留 UNKNOWN。

本轮确认并修复两个实现问题：Go GLM Flash 请求同时携带原生 thinking 字段时
被拒绝，改用保留指定强度的 reasoning_effort 请求；笔记解析在归属校验抛错后
可能残留已解析对象，修复为全部校验通过后才接受。历史表格中的“结构合格返回”
应理解为当时程序报告成功，并非修复后全量重验结论；已发现的归属错误不能算有效返回。

Flash 参数修复后经配置代理补测三项，12 轮均失败（10 次限流、2 次服务不可用）。
随后以修复后的校验和独立直连对照 GLM 5.3 high、Flash high、Grok 4.7 medium，
九项、36 轮仍全部失败（24 次限流、12 次服务不可用）。这是不同连接条件的新实验，
不能混入原轮次或视为单一代理故障，也不能据无输出推断模型语义能力。
限流及连接故障仍按失能计入分母；额度充足不保证没有限流。

这组内容证据支持把 Grok 4.6 medium 列为下一轮候选，尚不足以取代日常模型或宣称
稳定性优于 Luna medium。GLM 5.1/5.2 仅完成短合成连通探测，未完成真实笔记对照。
模型、推理档、代理与正式服务均未切换或部署。

## 下一阶段尚缺的依据

现有注册表聚合记录覆盖 2026-09-22 至 2026-10-10：19 个日历日中有 13 个记录日、
167 次 MCP/Console 调用。该 best-effort 窗口不证明未记录日没有使用，也不覆盖绕过注册表的
CLI、服务调用及全部月度维护/恢复职责。审计现在保留日期与覆盖口径；NOT_OBSERVED 仍不是退役授权。
后续完整交互流程退役需要明确产品取舍与兼容安排；本轮未删除公开能力或业务历史。首页重复的日历、Monitor/运行历史、盘后同步及本地维护卡片
已退役到各自的现有页面；笔记首页按需读取后台档案，未完成操作直接从原始记录读取。
调用边界、替代入口及回退见 [架构与性能](../guide/architecture-and-performance.md#note-home-read-scope-and-duplicate-view-retirement)。

期权完整条款仍需要可靠来源和其元数据时间，不能用符号提示或本地主表版本补造。
人工验收应分别确认仅用笔记及可选讨论/保存路径的语义、耗时与恢复体验，
并验证不经对话也能进入既有正式审阅流程；没有讨论记录不能被视为未完成任务。
合成 UI、启动与只读回归不能替代该反馈。已有安全边界和默认负担优化可独立交付。

## 暂停扩展的部分

Scorecard、Agenda、Trade Retro、内置 Research/Counter-review 不新增独立日常流程；
现有历史、API 和高级入口保留。多市场、Provider、图表等不因近期没有调用而被删除。
不引入第二个 Agent 框架、通用工作流引擎或独立状态数据库。

## 退役判定

- 静态引用只能找到部分调用者，合成审计 NOT_OBSERVED 不代表真实未使用。
- 使用统计至少覆盖两个完整周，同时核对月度、维护、恢复和调度等低频职责。
  窗口未覆盖的能力继续保留为可选项，不阻塞其他已证实冗余清理。
- 对外操作删除需要显式兼容迁移和旧客户端测试；不以减少工具数作为目标。
- 不删生产研究/成交/笔记历史，不重写旧迁移，不放松 Candidate 或订单确认。
- 生产迁移、发布部署、配置或调度变更按各自操作授权执行。

## 主流程验收底线

1. 笔记本身即可支撑主流程，Codex 对话、模型解释及讨论结论均非前置条件。核对持仓标的时提供可查询成交、跨账户持仓和相关衍生品，不要求用户重述已知事实。
2. 普通阅读或讨论不创建研究档案、不写状态、不强制每日 NO_ACTION，不隐式刷新券商或解释笔记。正式判断可不经对话，但仍需明确人工确认。
3. 来源认证失效、摘要正文缺失、成本冲突、历史截断均明确保留，不能声称数据最新完整。
4. 每个来源有精确身份、时间、币种及覆盖；相同标的不自动证明成交执行了某笔记/计划。
5. 按需保存结论后可回读，重试幂等；高级入口和未完成动作仍可恢复。
6. 不删除安全/恢复测试以减少测试成本。任何历史丢失、风险遗漏、权限变化都应暂停清理并回退。

本路线图不会自动创建监控或定时任务。下一批范围由上述验收与使用证据收敛。
